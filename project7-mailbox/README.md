# Проект 7: Приоритизація вхідної пошти

> LLM класифікує вхідні листи, детерміновані правила маршрутизують їх,
> термінові потрапляють у Telegram.

## Склад
- `inbox/` — 8 демо-листів (формат: From/Subject/Date/Body)
- `inbox-prioritizer.js` — класифікація + звіт + Telegram-алерти

## Результат прогону (24.10.2026) — 8/8 вірно
| Лист | Категорія | Пріоритет |
|---|---|---|
| m1 терміновий клієнт | customer | **high** |
| m2 рахунок на оплату | invoice | normal |
| m3 спам «зароби мільйон» | spam | low |
| m4 дайджест | newsletter | low |
| m5 новий магазин (запит умов) | customer | normal |
| m6 рекламація (розбите пиво) | claim | **high** |
| m7 внутрішнє (нарада) | internal | normal |
| m8 пропозиція логістики | partner | normal |

У Telegram надіслано лише high-priority (2 листи).

## Запуск
```
node inbox-prioritizer.js            # звіт
node inbox-prioritizer.js --send     # + Telegram
```

## Ключова ідея
«LLM розуміє, правила вирішують»: модель пропонує category/priority/summary/action,
а маршрутизація (що показати людині, що в архів) — детермінована й передбачувана.
Так зменшується ризик помилок моделі в критичних рішеннях.
