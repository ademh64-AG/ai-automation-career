# Проект 4: Чат-бот з базою знань (RAG) для дистриб’ютора

> Ретривал-аугментована генерація: бот відповідає на питання клієнтів
> ТІЛЬКИ на основі власної бази знань компанії (умови, доставка, асортимент).

## Склад
- `docs/*.md` — база знань (п’ять документів: асортимент, умови поставок, доставка, повернення, контакти)
- `build-index.js` — розбиває документи на чанки за розділами → `chunks.json` (23 чанки)
- `rag-bot.js` — векторний пошук (embeddings Gemini) + генерація відповіді (Groq/Gemini)
- `test-questions.csv` — 10 контрольних питань з еталонними джерелами

## Механіка (чесно)
1. **Індексація:** текст кожного чанка → embeddings (`gemini-embedding-001`) → кеш `chunks-embeddings.json`
2. **Отримання:** питання → embeddings → косинусна близькість до всіх чанків → топ-3
3. **Генерація:** LLM отримує «питання + контекст (топ-3)» та інструкцію відповідати лише за фактами; якщо відповіді немає — чесно відмовляється та дає контакт менеджера

## Результат оцінювання (10 питань)
- Точність вибору документа: **90%**
- Точність вибору розділу: **90%**
- Тестовий приклад: «Які умови доставки в Кривий Ріг і скільки коштує?» → «вівторок і четвер; безкоштовно від 15 000 грн, інакше 500 грн; розвантаження за рахунок отримувача»

## Запуск
```
node build-index.js                          # перебудувати індекс
node rag-bot.js --test                       # оцінювання на 10 питаннях
node rag-bot.js "Ваше питання"              # відповідь у консоль
node rag-bot.js "Ваше питання" --telegram   # + надіслати в Telegram
```

## Обмеження (чесно)
- Демо: база знань статична (5 документів); у проді — регулярне оновлення/додавання.
- Векторний індекс у пам’яті; для великих баз — векторна БД (напр. Qdrant/pgvector).
- Читання тільки з контексту: якщо питання поза базою — бот не фантазує, а спрямовує до менеджера.
