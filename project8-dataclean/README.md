# Проект 8: Очистка та збагачення даних клієнтів

> Гібрид: детермінована нормалізація телефонів + LLM-структуризація адрес
> + дедублікація за ключами.

## Склад
- `clients-raw.csv` — 14 «брудних» записів (різні формати телефонів, адрес, дублі)
- `data-cleaner.js` — очистка + звіт + Telegram

## Результат прогону (24.10.2026)
- Вхід: **14** записів → після очистки: **9**
- Нормалізовано телефонів: **12** (різні формати → `+380XXXXXXXXXX`)
- Структуровано адрес: **9** (місто / вулиця / будинок / квартира)
- Видалено дублів: **5** (за телефоном і за адресою)

Приклад: `м. Дніпро, вул. Шевченка 12` → `city=Дніпро, street=Шевченка, building=12`.

## Запуск
```
node data-cleaner.js            # звіт
node data-cleaner.js --send     # + Telegram
```

## Ключова ідея (для розповіді)
- **Правила** — там, де є чіткий формат (телефони): швидко й дешево.
- **LLM** — там, де потрібна семантика (адреси): надійно й гнучко.
- **Дедублікація** — комбінація ключів (телефон/адреса) з перевагою першого запису.
- Висновок: не все потрібно віддавати моделі; правильне поєднання правил і LLM — найкраща архітектура.
